# Test vectors

Official DMXReplay test vectors, per [`docs/SPECIFICATION.md` §19](../docs/SPECIFICATION.md#19-test-vectors).
Generated by [`generate_test_vectors.py`](generate_test_vectors.py):

```bash
python3 test-vectors/generate_test_vectors.py
```

| File | Test | Content |
|---|---|---|
| `test1_ramp.raw` / `.json` | 1 — Ramp | Every channel cycles `0..255` over 32 frames, 2 universes |
| `test2_alternating.raw` / `.json` | 2 — Alternating | Whole frame alternates `0x00`/`0xFF` every frame |
| `test3_random.raw` / `.json` | 3 — Random | Deterministic pseudo-random values across all 512 channels |
| `test4_multi_universe.raw` / `.json` | 4 — Multiple universes | 128 active universes, ramp pattern |
| `test5_sparse_universes.raw` / `.json` | 5 — Sparse universes | Source Art-Net universes (Port-Addresses `{1, 5, 17, 42}`, see `docs/ARTNET.md` §1.1) packed into rows `{0, 1, 2, 3}` — see the `.json` sidecar's `universes` field (`net`/`subnet`/`universe`/`port_address`) for the row mapping |

## File layout

`<name>.raw` is the concatenation of frames; each frame is the concatenation of its
per-row universes (512 bytes each), in row order — i.e. exactly the pixel source a
grayscale-encoding DMXReplay encoder would consume (`docs/SPECIFICATION.md` §5.1).
`<name>.json` records `frame_count`, `universes_per_frame`, `channels_per_universe`,
per-frame `timestamps_ns`, and (for the sparse vector only) the row → source-universe
`universes` mapping.

These vectors operate at the `dmxreplay.dmx` data-model level (`Universe`/`DMXFrame`)
and do not yet require the codec/container modules (Phase 4). Round-trip coverage is in
[`tests/test_dmx_model.py`](../tests/test_dmx_model.py). Tests 6–10 from the
specification (high packet rate, timing irregularity, seek, synchronization, loop)
require the recorder/player/sync engine and are tracked as Phase 2+ follow-up work, not
static files.
